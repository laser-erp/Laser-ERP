# Облачный агент и сервер Laser ERP

Инструкции для **облачного агента Cursor**, когда с домашнего ПК **нет доступа к серверу** (VPN, SSH).

## Роли

| Кто | Где работает | Задача |
|-----|----------------|--------|
| **Локальный агент** | ПК на E:, чат у владельца | Код, планы, правки; **пишет** задания сюда и **выкладывает на GitHub** |
| **Облачный агент** | Cursor Cloud / среда с доступом к серверу | **Читает** задание с GitHub, **выполняет** на VPS, **пишет отчёт** в тот же файл |
| **Владелец** | — | Даёт секреты облачному агенту, читает отчёт, пишет «продолжаем» локальному агенту |

## Где смотреть

- **Текущее задание:** [current-task.md](./current-task.md) (ветка **main**, папка `docs/cloud-agent/`).
- **Код проекта:** репозиторий `laser-erp/Laser-ERP`, ветка **main**.
- **Сайт:** https://laser-erp.armada.sx  
- **Сервер:** Ubuntu, приложение в `/var/www/laser-erp`, пользователь `lasererp`, systemd `laser-erp`.

## Секреты (не в GitHub)

В репозиторий **не кладём** пароли. Облачный агент получает доступ через **Secrets** в Cursor Cloud.

**Имена, которые уже использовал облачный агент:**

- `VPS_HOST` — `176.12.66.161`
- `VPS_USER` — обычно `root`
- `VPS_PASSWORD` — пароль SSH
- `VPS_SSH_PRIVATE_KEY` — опционально (если ключ битый — использовать пароль)
- `GITHUB_TOKEN` — для `git pull`, если репозиторий приватный (только `repo`, не публиковать)

Альтернативные имена из ранней документации (`SSH_HOST`, `SSH_USER`, …) — тоже можно, если так удобнее в Secrets.

На сервере Django читает `/etc/laser-erp.env` (Postgres, `DJANGO_SECRET_KEY` и т.д.) — **не копировать в Git**.

## Как облачному агенту работать

1. Открыть репозиторий с GitHub, прочитать **`docs/cloud-agent/current-task.md`**.
2. В шапке задания поставить **Статус:** `in_progress`, дату.
3. Выполнить шаги **по порядку**. Команды для сервера — в блоке «Шаги».
4. В конце заполнить раздел **«Отчёт облачного агента»** (факты, коды HTTP, ошибки). **Без паролей и ключей.**
5. **Сохранить изменения в истории проекта и выложить на GitHub** (главная ветка), чтобы локальный агент увидел отчёт.
6. Статус: `done` или `blocked` (если blocked — чётко написать, что нужно от владельца).

## Как локальному агенту выдавать задания

1. Отредактировать **`current-task.md`**: новая цель, шаги, обнулить/сменить отчёт.
2. Статус: `waiting`.
3. **Выложить на GitHub.**
4. Попросить владельца запустить **облачный агент** с текстом: «Выполни `docs/cloud-agent/current-task.md` и выложи отчёт на GitHub».

## Обновление сайта (типовой путь на сервере)

Если на VPS уже клон репозитория с `git`:

```bash
sudo bash /var/www/laser-erp/deploy/update_ubuntu.sh
```

Скрипт: `git pull`, зависимости, **миграции базы**, статика, перезапуск `laser-erp`.

Если `git pull` недоступен — описать в отчёте; локальный агент подготовит альтернативу (`tools/_sync_vps_code.py` с машины, где есть `.env.server`).

## Архив

Завершённые большие задания можно копировать в `docs/cloud-agent/archive/` (по желанию), в `current-task.md` — только актуальное.
